# 资源表单弹窗设计风格规范

本文档用于统一后台管理类弹窗表单的布局与视觉风格，当前以 `ResourceFormModal` 为基准实现，后续角色、用户、权限等表单可复用同一套设计语言。

## 目标

- 提升弹窗表单的层级感，避免字段简单纵向堆叠导致界面松散、冗长。
- 通过稳定的分组结构，让用户更快理解字段之间的关系。
- 统一后台系统内表单弹窗的视觉表达，降低组件风格漂移。

## 适用范围

- `src/views/system/**/components/*FormModal/index.tsx`
- 需要在 `MyModal` 内承载表单信息的新增、编辑类弹窗
- 以 Ant Design `Form` 为基础的后台管理页面

## 设计原则

### 1. 分区优先，不直接堆字段

表单内容应按业务语义拆分为 2 到 4 个区块，例如：

- 基础信息
- 资源配置
- 补充说明

每个区块必须有明确标题，优先复用 `@/components/SubTitle`，不要在业务组件里重复造标题样式。

### 2. 默认双列栅格

基础字段优先使用双列布局，减少表单纵向长度，增强后台界面的规整感。

- 推荐：`grid-template-columns: repeat(2, minmax(0, 1fr))`
- 推荐列间距：`24px`
- 长文本、备注、描述类字段：占满整行

不建议默认全部单列，除非字段本身明显依赖纵向阅读。

### 3. 字段按信息密度分层

字段摆放遵循“高频核心信息优先、补充信息后置”的原则：

- 第一屏优先放：名称、编码、类型、状态、父级关系
- 第二层放：与类型相关的配置字段
- 最后放：备注、描述、补充说明

### 4. 条件字段要稳定

当表单内容会因类型切换而变化时，布局要尽量稳定，避免界面频繁抖动或留白难看。

建议：

- `api` 类型：并排展示“接口路径 + 请求方法”
- `menu` 类型：路由路径独占一行
- `button` 类型：如果没有额外字段，可展示只读说明，而不是留空

### 5. 文案尽量具体

输入框占位符不要写成重复的“请输入XX”式空泛文案，优先给出真实示例：

- `例如：用户列表、角色删除`
- `例如：/api/users/list`
- `例如：/system/user`

这类提示可以明显降低用户的理解成本。

## 当前推荐结构

以资源表单为例，推荐结构如下：

### 基础信息

- 资源名称
- 资源编码
- 资源类型
- 父级 ID

### 资源配置

- `api`：接口路径、请求方法
- `menu`：路由路径
- `button`：只读说明或轻提示

### 补充说明

- 备注

## 组件复用约定

### 标题组件

- 统一使用 `@/components/SubTitle`
- 业务组件只允许通过 `className` 调整间距，不重复实现左侧色条标题

### 弹窗宽度

- 简单表单：`640`
- 双列表单：推荐 `720`
- 字段较多且包含长文本时，可按实际情况继续放宽

### 文本域

- `remark`、`description` 默认使用 `Input.TextArea`
- 推荐 `rows={3}`
- 推荐开启 `showCount`
- 推荐设置合理的 `maxLength`

## 样式约定

表单样式应尽量保持“结构型样式”而非“装饰型样式”，重点控制以下内容：

- 区块之间的垂直间距
- 栅格列数与列间距
- 全宽字段跨列规则
- 只读提示输入框的弱化背景

避免在每个弹窗里单独定义一套标题颜色、装饰线、卡片边框，优先抽公共组件与公共节奏。

## 推荐做法

```tsx
<div className={styles['section']}>
  <SubTitle title='基础信息' className={styles['sectionTitle']} />
  <div className={styles['formGrid']}>
    {/* 两列字段 */}
  </div>
</div>
```

```less
.formGrid {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 0 24px;
}

.fullWidth {
  grid-column: 1 / -1;
}
```

## 禁止项

- 禁止所有字段直接纵向堆叠且没有分区标题
- 禁止在每个页面里手写一套新的 subtitle 样式
- 禁止条件字段切换后出现大片无意义空白
- 禁止备注、描述等长文本字段仍挤在半列中显示
- 禁止占位文案全部使用机械重复的“请输入”

## 后续落地建议

- 将 `RoleFormModal`、`UserFormModal` 等弹窗逐步统一到这套结构
- 如果后续弹窗普遍采用相同布局，可继续抽一个公共的表单分区容器组件
- 如果需要让 AI 在后续开发中持续遵循该规范，可再同步一份到 `.cursor/rules/`
